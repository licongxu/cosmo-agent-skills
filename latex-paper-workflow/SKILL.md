# LaTeX paper workflow

**Deliverable:** a reproducible manuscript PDF built from source plus figure files
in the project. Figures are not chat screenshots or ad hoc images.

## Principles

1. **Figures live in the paper tree** as PDF (or project-approved high-quality
   raster), generated by the project's plot scripts and named consistently.
2. **Compile** the manuscript after substantive edits using whatever build command
   the project already documents. Do not invent a new toolchain in the skill.
3. **Debug by looking:** after each build, open the PDF (or page images) and run
   **vlm-figure-audit** on figures, tables, and problem pages. Layout issues
   (float clashes, cramped tables, illegible text) are fixed by editing sources
   and recompiling, then re-checking visually. Do not teach or paste LaTeX
   layout commands as the primary fix.
4. **Plot quality** is governed by **scientific-plotting** and verified by VLM,
   not by scaling figures in the manuscript to compensate for bad exports.
5. **Captions** state what the reader needs (units, sample size, version) per
   project convention and must match what VLM shows.

## Do not

- Ship without visually inspecting the compiled PDF near final layout.
- Treat "compiles without error" as sufficient.
- Patch unreadable figures only in the manuscript; regenerate the figure asset.
- Dump LaTeX or plotting code in chat instead of editing project files.

## Workflow

1. Update plot scripts or manuscript text in the repo.
2. Regenerate figure PDFs; VLM-audit each figure.
3. Compile the paper; VLM-audit pages with new or moved floats and tables.
4. Record validator status in the project manifest if one exists.
